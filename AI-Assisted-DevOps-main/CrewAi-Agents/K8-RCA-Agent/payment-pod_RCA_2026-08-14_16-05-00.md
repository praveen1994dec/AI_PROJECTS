# 🚨 Kubernetes Incident Report: payment-pod

## 📋 Incident Summary
The `payment-pod` in the `prod` namespace is currently in a `CrashLoopBackOff` state after repeatedly being terminated by the Kubernetes node. The pod has restarted 6 times in the last 45 minutes, resulting in intermittent failures for the checkout service.

## 🔍 Root Cause Analysis
The pod is failing because the application is exceeding its configured Kubernetes memory limits, resulting in an `OOMKilled` (Out of Memory) state. 

* **Event Correlation:** The Kubernetes events log shows multiple `Warning` events with the reason `OOMKilling`: `Memory cgroup out of memory: Killed process 1234 (java)`.
* **Log Evidence:** Immediately prior to each container termination, the application logs output a fatal stack trace: `Exception in thread "http-nio-8080-exec-4" java.lang.OutOfMemoryError: Java heap space`.
* **Configuration Verification:** Reviewing the Pod's YAML manifest reveals that `resources.limits.memory` is strictly hardcapped at `256Mi`. The Spring Boot Java application requires more base memory to handle spikes in transaction processing, causing the JVM to exceed the container's cgroup limit and get killed by the kubelet.

## 🛠️ Resolution Guide
To resolve this, we need to increase the memory resources allocated to the container so the Java application has enough overhead to process transactions without hitting the cgroup ceiling.

### Immediate Fix (Commands)
You can immediately patch the running deployment to increase the memory limit to `512Mi` and force a rollout of a new, stable pod. Run this command in your terminal:

```bash
kubectl set resources deployment payment-service-deployment -c payment-container --limits=memory=512Mi,cpu=500m --requests=memory=256Mi,cpu=200m -n prod
```

### Permanent Fix (YAML Configuration)
Update your source code repository (e.g., Helm chart or Kustomize manifests) to permanently increase the memory limits. Update the resources block in your Deployment YAML as follows:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: payment-service-deployment
  namespace: prod
spec:
  template:
    spec:
      containers:
      - name: payment-container
        image: registry.internal/payment-service:v1.4.2
        # UPDATE THE RESOURCES BLOCK BELOW
        resources:
          requests:
            memory: "256Mi"
            cpu: "200m"
          limits:
            memory: "512Mi"  # Increased from 256Mi to fix OOMKilled
            cpu: "500m"
```
